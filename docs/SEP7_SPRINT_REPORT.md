## Unresolved defects and known risks

1. **`v_recipe_cost_current` is ambiguous under a tie.** Two snapshots written in
   the same transaction share `now()`, and `distinct on … order by computed_at
   desc` then picks arbitrarily (check 20). Production does not hit it because
   each PostgREST request is its own transaction — which makes **one recompute
   per action** a rule the code follows deliberately, not a coincidence. A
   durable fix is a monotonic tiebreak on `cost_snapshots`; **not attempted**,
   because it rewrites a live table for a case production cannot currently reach.
2. **Entitlement UI is date-based, not function-based.** `fn_my_entitlement_status()`
   lives in `0032`, which is not authorised. Today `/account` reads
   `current_period_end` and states it as a fact; write refusals are translated at
   the point of failure. **No entitlement predicate is reimplemented in
   TypeScript.** When `0032` ships, the page should read the function instead.
3. **`ingredient_prices`, `cost_snapshots` and `recipe_prices` are not
   entitlement-gated** (spec F5): `0004` gave them `for all` policies, and
   `0028` selected by the name pattern `^p_.*_(insert|update|delete)$`. Once
   trials genuinely expire, a lapsed user could still write prices while unable
   to add an ingredient. **Verification-only (V-7), unchanged, still unverified
   against live `pg_policies`.**
4. **Recipe edit has no optimistic UI.** Every mutation is a full server round
   trip and reload. Correct and simple; on a poor connection it will feel slow.
5. **No sub-recipe UI.** The column and the cycle guard exist; the screen does
   not. Deferred deliberately.
6. **Labour and overhead are excluded**, and the page says so in plain words.
7. **Ingredients cannot be edited or deactivated** from the UI yet.
8. **`0038`/`0040` plan limits remain unenforced**, so launch copy must not quote
   the trial's 1 business / 2 users / 20 recipes.

## Recommendation: **CONDITIONAL GO for 7 September**

The journey exists and the arithmetic is right. ₦9,000 for 2 paint becomes
₦1.125/g, 2,000 g of it becomes ₦2,250 a batch, ₦281.25 a portion and a 43.75%
margin at ₦500 — computed by Postgres, verified against real RLS, rendered
truthfully on a phone. Where a price is missing the product says which
ingredient and refuses to show a cost, which is the promise that matters most.

**Conditions, in order:**

1. **One full manual pass against a real Supabase project** — a disposable one,
   not production. PostgREST is the single link no test here exercised, and
   column-name or filter mistakes surface only there.
2. **Resolve V-7** with the read-only `pg_policies` query before the trial gate
   goes live, or the ended-trial experience is incoherent — no new ingredients,
   but new prices allowed.
3. **`0031`/`0032` still need owner authorisation**, and `0032` waits on the D-3
   classification result. Without `0032` trials do not actually expire, so the
   `/account` message is honest but unenforced.
4. **Launch copy must omit the trial limits** until `0038`/`0040` ship.

**NO-GO if** condition 1 is skipped. Everything else can ship with a known,
stated gap; shipping a costing product whose only untested link is the one
between the browser and the database cannot.
