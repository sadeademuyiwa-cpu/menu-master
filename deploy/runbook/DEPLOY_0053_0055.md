## The mailer

`supabase/functions/platform-alert-mailer` sends one digest email per run for
open alerts not yet notified, then stamps `notified_at`. It needs three
secrets in the edge-function store (never in the repository, never in Vercel):

| Secret | What |
|---|---|
| `RESEND_API_KEY` | from resend.com (free tier) |
| `ALERT_EMAIL_TO` | where the digest goes |
| `ALERT_EMAIL_FROM` | a sender on a domain verified in Resend, e.g. `alerts@menumasterng.com` |
| `MAILER_TOKEN` | any long random string; the caller must present it as `x-mailer-token` |

```
supabase functions deploy platform-alert-mailer --no-verify-jwt
supabase secrets set RESEND_API_KEY=… ALERT_EMAIL_TO=… ALERT_EMAIL_FROM=… MAILER_TOKEN=…
```

Schedule it after the scan (Supabase → Integrations → Cron, or `pg_cron` +
`pg_net` with the token in Vault): `POST https://<ref>.functions.supabase.co/platform-alert-mailer`
with header `x-mailer-token: <MAILER_TOKEN>`, at `12 * * * *`. Until it is
scheduled, the `/admin/alerts` page still shows everything; only the email is
missing.
